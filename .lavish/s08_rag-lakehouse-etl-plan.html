project 1 · branch rag · databricks-propertyiq

Port transcript·lab's RAG pipeline to the lakehouse — with a periodic ETL feeding everything in.

A local exporter reads transcript·lab's stores (Chroma SQLite, eval JSON, graph cache) and lands updates-only Parquet on a UC Volume on a schedule. The proven propertyiq machinery — Auto Loader, file-arrival job, bundle — turns it into Delta tables; a Vector Search delta-sync index embeds the chunks; a RAG ChatAgent retrieves from it; and transcript·lab's own golden set + IR metrics score Databricks retrieval against the Chroma baseline.

probed: VS endpoint ONLINE ✓ probed: gte / bge / qwen3 embeddings ✓ 2,966 chunks · 107 videos · 20 golden Qs · 1,931 graph extractions

Goal & current state

Goal: everything transcript·lab knows, continuously available in Databricks — queryable as Delta, retrievable through Vector Search, answerable by a deployed RAG agent, and measured against the local Chroma baseline using the eval assets transcript·lab already ships.

  • Current state: transcript·lab is 100% local — Chroma SQLite (150 MB, 4 collections), MiniLM 384-dim embeddings, Neo4j graph, JSON eval artifacts. Zero Databricks code. propertyiq main@0592b4e has the entire delivery chain this plan reuses: Volume landing + sha-dedup feed contract, Auto Loader, bundle jobs with file-arrival triggers, ChatAgent + agents.deploy, benchmark graders, verdict dashboards.
  • Desired behavior: run make rag-export (or let the schedule do it) → new/changed transcript data lands → the workspace ingests, syncs the index, and the agent answers from fresh data. Re-runnable any day with no manual steps.
  • Key acceptance test: ask rag_transcript_agent (UC model workspace.rag.rag_transcript_agent, served via agents.deploy) any question in its Review App chat and it answers through the agentic RAG path — retriever-tool hops visible in the decision log, answer cited to video + timestamp. That single interaction is the definition of done for phases 1–4.
  • Where the code lives: branch rag of databricks-propertyiq. The exporter reads ../transcript-rag-agent/.yt-agent/ read-only (path via RAG_SOURCE_DIR env; transcript-rag-agent is not modified). New UC schema: workspace.rag.
Two probes already de-risked the plan live: vector-search-endpoints create-endpoint succeeded on Free Edition (endpoint propertyiq-probe, state ONLINE, currently empty — phase 1 renames the concept: delete it and create rag-search), and the workspace serves three FMAPI embedding models (databricks-gte-large-en, databricks-bge-large-en, databricks-qwen3-embedding-0-6b).

The periodic ETL — same contract as the property feed

One new script, scripts/rag_export.py, mirroring the proven propertyiq landing contract so the whole ingest side is reuse:

  1. Read — direct SQL over chroma.sqlite3 (joins embeddings → embedding_metadata; no Chroma client, no embedding model load) + JSON parses for the artifact files. Read-only on RAG_SOURCE_DIR (default ../transcript-rag-agent/.yt-agent).
  2. Diff — build each entity's snapshot as a DataFrame, compute per-entity content sha; write <entity>_<sha8>.parquet only when the sha differs from the last landed file (exact propertyiq_getdata dedup contract — re-runs are free no-ops).
  3. Land — upload via databricks fs cp to /Volumes/workspace/rag/landing/<entity>/. The file-arrival trigger on the volume (60s settle, 5-min floor — same tuning as the medallion job) wakes rag_ingest.
  4. Ingest — Auto Loader (parquet, rescue mode, versioned schemaLocation) → bronze append with _metadata.file_path lineage → silver MERGE on the natural keys above. Chunk deletes (a video re-indexed with fewer chunks) are handled by a full-outer anti-join against the latest snapshot batch — rows missing from the newest snapshot for a video_id are flagged is_current=false, never hard-deleted.
  5. Sync — final job task triggers the Vector Search index sync (TRIGGERED pipeline type) so the index follows every ingest without polling.

Periodicity — two layers

  • Laptop → volume: decided (D3) manual make rag-export, run whenever the local corpus changes. No launchd/cron — the target is idempotent and sha-deduped, so running it is always safe and a no-op when nothing changed. (A schedule can be added later without touching any code.)
  • Volume → tables → index: fully event-driven in the workspace (file-arrival → job → index sync). Nothing runs (or costs quota) when no data lands — so "periodic" is exactly as often as you run the export.

Vector Search: two indexes, one comparison

Delta-sync indexes on silver_chunks (CDF is already on — it's the delta-sync prerequisite). Embedding input is embedding_text = context_header + "\n" + text, exactly what transcript·lab embeds, so the comparison is apples-to-apples:

Endpoint: delete the empty propertyiq-probe, create rag-search (STANDARD). probe first Free Edition index-count and managed-embedding quotas are unverified — phase 1 creates the gte index and checks whether a second fits; if not, the MiniLM control drops to a vector_search()-over-SQL fallback and the story survives.

Eval: transcript·lab's golden set, re-verified, three-way

Port ir_metrics.py (recall@k, MRR, NDCG — pure functions) into src/lib/ with the golden 20 questions. One correction first: the golden expected_chunk_ids were verified against a 23-video / 488-chunk corpus and chunk ids churn on re-index — so expected videos stay authoritative (expected_video_ids are stable), and chunk-level hits are re-anchored by matching golden chunk text-shas against today's silver_chunks. Questions whose anchors don't resolve get flagged for a confirm pass (the s06 pattern) before counting.

  • Contenders: retrieval-level first — local Chroma (MiniLM, the baseline) vs rag_chunks_gte vs rag_chunks_minilm (recall@10/MRR/NDCG per domain). Then end-to-end: the deployed agent answers all 20 in each mode (single / multi / agentic), graded by the deterministic-grader pattern — a modes × index matrix, echoing transcript·lab's own eval-matrix design.
  • Agent — rag_transcript_agent, one deployment, three answer modes, porting transcript·lab's answer paths onto Vector Search (registered as workspace.rag.rag_transcript_agent):
    • single — one retrieval (VS query, top-8, score floor) → cited answer. Port of the single-hop rag_transcript_agent path.
    • multi — recursive multi-hop: decompose → retrieve per sub-question → synthesize, bounded depth 2. Port of the recursive path.
    • agentic default — LangGraph ReAct loop where the LLM calls the retriever tool as many times as it decides (capped), then answers. Port of rag_agent.py's agentic path.
    All three live in one ChatAgent; the caller picks via custom_inputs={"mode": "..."} (the Review App and benchmark exercise all three; custom_outputs returns retrieved chunk ids + decision log per hop, feeding the IR metrics directly). Registered with declared resources (DatabricksVectorSearchIndex + LLM endpoint + tables — the v3 auth lesson applied on day one), deployed once via agents.deploy.
  • Verdict dashboard: rag_eval results table → bundle-managed dashboard: metric bars per contender, per-domain breakdown, latency, and the pass/fail detail grid.
delivery

Five phases, each independently demoable

1

Foundations & probes

branch rag · schema+volume · endpoint rag-search · index-quota probe

Create workspace.rag schema + landing volume via bundle; replace propertyiq-probe with rag-search; create a throwaway 10-row delta-sync gte index to prove the managed-embedding path and learn the index quota. Exit: index answers a similarity query.

2

Exporter ETL

scripts/rag_export.py · sha-dedup parquet · make rag-export (manual, D3)

SQLite + JSON readers, snapshot diffing, volume upload, unit tests on the readers/shas (fixtures from real rows). Exit: two consecutive runs — first lands ~10 files, second lands zero.

3

Lakehouse ingest

rag_ingest job · Auto Loader bronze · silver MERGE + is_current · DQ checks

File-arrival-triggered job, bronze→silver notebooks, CDF on chunks, DQ task (key uniqueness, chunk-count vs transcript coverage, embedding-dim check). Exit: counts match source (2,966 / 107 / 20…) and a re-export changes nothing.

4

Index + rag_transcript_agent (3 modes)

rag_chunks_gte (+minilm) · workspace.rag.rag_transcript_agent · agents.deploy

Production indexes with post-ingest sync task; one ChatAgent carrying the three ported answer modes (mode via custom_inputs, chunk ids + decision log in custom_outputs); register with declared VS resources; deploy (delete old versions first — the quota lesson). Exit = the key acceptance test: ask rag_transcript_agent a question in the Review App and it answers via agentic RAG with correct video citations (then verify single/multi too).

5

Eval + verdict

golden re-anchor + confirm page · 3-way retrieval metrics · dashboard · PR

Re-anchor golden chunk ids, s09 confirm page for unresolved anchors, run the 3-way benchmark, ship the verdict dashboard, PR the branch through no-mistakes. Exit: dashboard shows the Chroma-vs-VS verdict on confirmed goldens.
