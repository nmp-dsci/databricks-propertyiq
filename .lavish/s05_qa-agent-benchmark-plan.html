agent_bench · branch plan

One golden set, three QA agents: Genie vs LangGraph vs Data Pilot

Ask the same question across three sources — the managed Genie space, a LangGraph agent on Databricks, and the existing Data Pilot chat in data-qa-agent — and compare the answers against one golden set. The LangGraph agent is deliberately a port of Data Pilot's data-agent: same stages, same report shape (a number with a basis, a trend, a caveat), but grounded in the Unity Catalog gold tables instead of the dbt manifest, executing on the warehouse instead of Postgres. The verdict lands as an AI/BI dashboard.

Current state → desired behavior

Today

  • Genie space is live over the gold tables with grounding instructions (re-aggregate additive legs, volume floors, no suburb join between rent and sales). Chat exists in the Databricks UI only.
  • data-qa-agent ("Data Pilot") runs locally: login → chat → NL→SQL over marts.property_rent/_sales in Postgres → report with KPIs, trend chart, insights. It has an eval-case format (evals/cases/*.yaml: question, tier, golden_sql, grader, authoring_status) covering the same NSW datasets.
  • No LangGraph agent exists yet; no cross-agent comparison exists anywhere.

After this branch

  • A LangGraph agent answers the same questions on Databricks — grounded in the gold tables, registered in Unity Catalog, callable as an endpoint.
  • A golden set of ~20 questions (ported from data-qa-agent's eval cases + Databricks-specific traps) with confirmed reference answers computed by deterministic SQL.
  • A benchmark harness runs Genie, LangGraph, and Data Pilot over the set and writes propertyiq_ml.agent_benchmark.
  • An AI/BI dashboard shows the verdict (accuracy, groundedness, latency per agent) with the Genie space linked for live "ask the data" chat — the Databricks replica of the Data Pilot experience.
The deliverable is the comparison, not any single agent — same shape as the s03 forecast bake-off: one honest harness, identical inputs, a verdict table an interviewer can read in ten seconds.

the decision surface

Three contenders, one question set

A · Genie space

exists

Databricks-managed NL→SQL, grounded by curated instructions on the space.

build cost
None — already live. Harness drives it via the Genie Conversations API (poll message → read query attachment + result).
strengths
Zero code, UC-governed, instructions already encode the trap rules (additive re-aggregation, volume floor, no suburb join).
weaknesses
Answers stop at SQL + table; no narrative insight, no chart choice, no multi-step reasoning. Instructions live workspace-side, not in git.
surface
Genie chat UI; embeddable as "Ask Genie" on the AI/BI dashboard.

B · LangGraph agent

build

A port of Data Pilot's data-agent to Databricks: same stages and report shape, re-grounded on the catalog instead of dbt.

build cost
The core of this branch. ChatDatabricks on FMAPI (llama-3.3-70b — proven live via ai_query); the pipeline copies data-qa-agent's agent design, swapping dbt-manifest grounding for UC schemas + table comments and Postgres execution for the warehouse (see the port map below).
strengths
Full parity ambition with Data Pilot: decision log, retries, insight phrasing, KPI + trend report — a direct apples-to-apples of "same agent, dbt/Postgres vs Unity Catalog/Delta". Logged with MLflow models-from-code as a ChatAgent → UC registry → served endpoint.
weaknesses
Everything Genie gives for free must be earned: SQL safety, governance, prompt-injection posture. agents.deploy() unverified on Free Edition (fallback: plain CPU serving of the ChatAgent, proven in s03).
surface
Serving endpoint → callable from SQL (ai_query), notebooks, or a chat app.

C · Data Pilot

exists

The data-qa-agent stack — the UX target, running on the same NSW data in Postgres.

build cost
None to build; make up + make pipeline-full locally, then drive /ask over HTTP with the same questions.
strengths
Richest answers today: KPIs + trend chart + written insights + decision log, under RLS. It is the bar the Databricks agents must reach.
weaknesses
Different engine (Postgres marts vs Delta gold) — golden answers must be checked to match across both, or scored with tolerance. Not on Databricks, so it's the external yardstick, not a deployable.
surface
Its own chat UI at localhost:5230.
Decided (D1): the line-up is exactly these three — Genie, LangGraph, Data Pilot. No naive-baseline calibration floor.

Scoring — two layers, same as data-qa-agent's graders

  • Deterministic (primary): did the answer contain the confirmed value within tolerance (5%)? For list questions: set overlap on the top-k. For traps: did it apply the rule (re-aggregate, floor, refuse)?
  • LLM judge (secondary): mlflow.genai.evaluate with groundedness + relevance judges on FMAPI — catches confident-but-wrong prose the value-check misses.
  • Operational: wall-clock latency and answer length per agent.

Deterministic scores decide the verdict; judge scores annotate it. A benchmark where the judge alone decides is a vibe, not a measurement.

The golden set — drafted, not yet confirmed

Start with a seed of 3 questions — one per gold table — take those all the way through the loop (confirm → run all agents → score → dashboard), then grow the set toward ~20. A thin end-to-end slice first proves the harness before any authoring effort is sunk into questions.

#TableSeed questionGolden answer basis
1gold_property_rent"What's the median weekly rent for a 2-bedroom unit in postcode 2000 right now?"Direct lookup: latest month, postcode 2000, unit, band '2' (ported from data-qa-agent's T1 case).
2gold_property_sales"Which postcodes had the highest average house sale price over the last 12 months?"Trap built in: must re-aggregate sum(total_sale_value)/sum(n_sold) and apply a volume floor.
3gold_property_yield"Which postcodes currently give the best gross rental yield for units?"Latest-month ranking from the yield mart — tests whether agents find/derive yield correctly.

The full set then grows to ~20 in evals/golden_qa.yaml (same shape as data-qa-agent's cases: question, tier, golden_sql, expectation, authoring_status): ported from data-qa-agent/evals/cases/ (nsw_rent, nsw_sales, nsw_yield — re-grounded from marts.* to the gold tables), plus trap questions and refusal checks:

TierCountExampleWhat it tests
T1 lookup6"Median weekly rent for a 2-bed unit in postcode 2000 right now?"Point accuracy: correct filter, correct latest month.
T2 trend6"How has average rent in 2145 moved since 2020?" / "Rent trends 2077 vs 2076"Time-series handling, correct aggregation over months.

Confirmation is a blocking step (Phase 1), and it's yours — via an s06 review page (decided, D3). Every question ships with a golden_sql that I run against the gold tables on the warehouse; the computed values become the candidate answers with authoring_status: draft. I'll bring the question × candidate-answer table back as an s06 lavish page with per-row confirm/edit controls (mirroring data-qa-agent's Golden Examples authoring page) — only confirmed rows count toward the verdict. Data Pilot's Postgres marts are checked against the same values; where the two platforms legitimately disagree (load-window differences), the case records a per-case tolerance or is dropped.

Output surfaces — replicating Data Pilot on Databricks

1 · Benchmark verdict dashboard committed

An AI/BI dashboard (deployed via the bundle, like the existing PropertyIQ dashboard) over agent_benchmark: score by agent × tier (grouped bar), accuracy vs latency (scatter), per-question detail table with each agent's answer side by side, and KPI counters (overall accuracy per agent). The Genie space is linked on the dashboard, so a viewer can pivot from "the verdict" to "ask the data yourself" — chat and dashboard on one surface, which is the closest native equivalent of Data Pilot's chat-plus-report page.

Genie already has a chat UI. For the LangGraph agent: probe Databricks Apps first (a small Streamlit/Gradio chat calling the endpoint — the truest Data Pilot replica; a 5-minute availability check in Phase 2). If Apps aren't available on Free Edition, fall back to the endpoint's built-in query UI + ai_query from SQL — zero build, proven live in s03.

2

LangGraph agent, registered and served

src/lib/qa_agent.py (the Data Pilot agent graph ported to UC/warehouse per the map above; guardrails included, unit-testable with a stubbed LLM) + src/notebooks/agent/01_log_register.py (MLflow ChatAgent → UC) + 02_deploy.py (agents.deploy, falling back to plain serving) + resources/jobs/agent_bench.yml. Delivered when

  • UI: model visible in Catalog Explorer under propertyiq_ml.qa_agent; endpoint Ready in Serving.
  • SQL: ai_query('<endpoint>', ...) returns an answer from the warehouse.
3

Run the benchmark, three ways — locally

The harness runs on the laptop (scripts/run_benchmark.py), because that's the only place all three agents are reachable at once: Genie and the LangGraph endpoint are HTTPS APIs callable from anywhere, but Data Pilot lives on localhost — a Databricks job can never reach it. The local runner drives all three live, scores with the graders + mlflow.genai.evaluate (logging to the workspace MLflow tracking server), and writes agent_benchmark to Delta via the SDK. A workspace-job variant stays possible for Genie + LangGraph only (e.g. scheduled regression runs), but the three-way comparison is local by construction.

Delivered when
  • CLI: make benchmark (local) succeeds with Data Pilot up; verdict query on agent_benchmark returns one row per agent × tier.
  • UI: workspace MLflow experiment shows per-question traces and judge scores.
4

Verdict dashboard + chat surface

AI/BI dashboard from agent_benchmark (bundle-deployed), Genie space linked; LangGraph chat surface per D2 outcome. s06 lavish tour with screenshots, same treatment as s04.

Delivered when
  • UI: published dashboard shows scores per agent; Ask-Genie works from it; you can ask the LangGraph agent a question through the chosen surface.
  • CLI: databricks bundle validate/deploy clean; PR through /no-mistakes.
